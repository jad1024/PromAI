# 指标列表 / 巡检模版 优化方案

> 写于 2026-08-29。当前痛点：指标数量膨胀后查找/复用困难、跨数据源模板复制繁琐、缺乏分组与版本管理、批量操作需要逐条配置。

## 一、现状摘要（基于 `Metrics.vue` / `InspectionTemplates.vue` / `DataSources.vue` 代码）

| 模块 | 现状 | 痛点 |
|---|---|---|
| **指标配置**（Metrics.vue） | 单一平铺列表 + 手动 `类型管理` 弹窗；只支持按数据源过滤；没有标签/搜索/排序之外的导航 | 数量上去后（如 200+ 条）找一条指标要逐行翻；类型只有名字，没有描述/图标/排序/层级 |
| **巡检模板** | 按 `name` 模糊搜索 + 单个 `apply` / 复制；模板与数据源通过 `template_ids` 数组多对多绑定 | 模板之间的差异只能从指标列表里比较；批量绑定要靠"批量操作对话框"手工选；没有"模板族"概念（如 MySQL 高可用 / Linux 系统监控 这种分类） |
| **数据源 → 模板** | `apply` 时按名字复制指标，遇到同名按时间后写覆盖前写 | 重名冲突不可见、覆盖前无提示；多模板合并顺序靠人工记忆 |
| **删除** | 单条确认；删除类型会把全部子指标删掉 | 误删风险；缺少"软删/归档"能力 |

---

## 二、建议改造的总体目标

1. **指标**：从"长平铺表"升级为"按类型分组 + 搜索 + 收藏 + 标签"，并支持快速预览 PromQL 与当前值。
2. **巡检模板**：引入"模板分类（族）"与"版本快照"，模板之间支持 Diff / 合并 / 一键应用到一组数据源。
3. **跨集群复用**：模板与全局指标解耦，用"导入全局指标"显式控制流向，导入冲突可视化。
4. **批量操作**：模板/指标的批量操作走"批量子任务"模型，复杂场景不再卡在对话框。

## 三、指标列表优化（Metrics.vue）

### 3.1 左侧类型导航 + 右侧表格

```
┌───────────────┬─────────────────────────────────────┐
│ 类型          │  [搜索] [标签过滤] [+ 新建指标]      │
│ L7 主机       │ ─────────────────────────────────  │
│  ├ CPU (12)   │  ▢ 名称       PromQL        操作    │
│  ├ 内存 (8)   │  ▢ CPU使用率  rate(...      ⋯     │
│  └ 磁盘 (15)  │  ▢ 内存使用率  rate(...      ⋯     │
│ L8 应用层     │  ...                               │
│  └ MySQL (6)  │                                    │
│ 📌 收藏 (3)   │                                    │
│ 🗑️ 归档       │                                    │
└───────────────┴─────────────────────────────────────┘
```

### 3.2 数据模型扩展

`metric_types` 表新增字段：

| 字段 | 类型 | 作用 |
|---|---|---|
| `icon` | string | 类型图标（Element Plus icon 名），侧边导航用 |
| `color` | string | 类型标识色 |
| `parent_id` | uint | 支持二级分组（如 "L7 主机" → "CPU"） |
| `sort_order` | int | 自定义排序 |
| `description` | string | 鼠标悬停说明 |
| `archived` | bool | 归档而非硬删，指标数 > 0 时禁止删除但允许归档 |

`metric_configs` 表新增字段：

| 字段 | 类型 | 作用 |
|---|---|---|
| `tags` | JSON `[]string` | 自由标签（如 `["mysql", "replication"]`），用于过滤 |
| `favorite` | bool | 用户级收藏，显示在"📌 收藏"组 |
| `unit` | string | 已有，但可考虑加"展示精度"字段 |
| `updated_at` | time | 模板导入时间追踪 |

### 3.3 UI 改造点

- **搜索框升级**：支持 `name:cpu type:L7 tag:mysql` 这类轻量查询语法（参考 Grafana Explore）。
- **PromQL 列改为可展开**：默认单行省略，hover 显示完整；点击展开显示最近一次巡检值（直方图缩略图）。
- **批量编辑**：多选 → 批量改阈值 / 级别 / 标签，避免逐条改 200 条。
- **导入/导出**：支持把全局指标导出为 YAML；跨 PromAI 实例复用。

### 3.4 删除安全

- 删除类型前必须先归档全部子指标（或显式确认）。
- 已绑定的指标在 `metric_configs` 的引用计数，删除前提示"被 N 个模板/数据源使用"。

## 四、巡检模版优化（InspectionTemplates.vue）

### 4.1 模板族（Category）

`inspection_templates` 新增 `category` 字段或独立 `template_categories` 表：

```
- 基础设施
  ├ Linux 系统监控（23 指标）
  ├ Windows 系统监控（12 指标）
  └ 网络设备（8 指标）
- 数据库
  ├ MySQL 监控（15 指标）
  ├ PostgreSQL 监控（14 指标）
  └ Redis 监控（6 指标）
- 中间件
  ├ Kafka（9 指标）
  └ Nginx（5 指标）
- 自定义
  └ 业务模板 v1（7 指标）
```

UI：侧栏分类（类似指标类型），顶部按类目过滤。

### 4.2 模板版本快照

`template_versions` 表（与 `inspection_templates` 多对一）：

| 字段 | 作用 |
|---|---|
| `version` | `v1.2`，每次"发布"递增 |
| `snapshot_json` | 模板内全部指标配置的完整 JSON 快照（阈值、PromQL、标签） |
| `created_by` / `created_at` | 审计 |
| `note` | 版本说明（"修复 MySQL 阈值"） |

应用模板到数据源时，记录 `applied_version`；数据源回滚到历史版本时可一键切换。

### 4.3 模板 Diff 与合并

新增页面 `/templates/diff?from=1&to=2`：

- 左右两栏对比两个版本
- 增/改/删指标高亮
- 黄色 = 阈值/级别变化，绿色 = 新增，红色 = 删除
- 支持"应用此 diff 到选中数据源"按钮

模板之间也能 Diff：把 `templateA` 与 `templateB` 合并为 `templateC`，可视化差异点。

### 4.4 跨集群复用

- **YAML 导入** 已有 → 强化为可读 diff。
- **多模板合并** 行为明确化：勾选"后导入覆盖先导入"或"按字段优先级合并"；UI 上把合并顺序拖动排序。
- **绑定检查**：数据源页批量"绑定模板"时，按"已绑定的指标"对比，避免重复。

## 五、批量操作改进（DataSources.vue / Metrics.vue）

### 5.1 现状问题

- 选 50 个数据源批量绑定 5 个模板，要在一个下拉里选 5 项，UI 挤。
- 批量操作是同步阻塞的，失败无法重试。

### 5.2 引入批量子任务

后端新增 `batch_tasks` 表（`type / payload / status / result / created_at`），前端调用 `POST /api/promai/batch-tasks` 返回 task_id，轮询或 SSE 获取进度。

- 进度可见：已完成 X / 总 Y / 失败 Z
- 单条失败不阻断其他项
- 失败项可"重试失败项"

适用于：批量绑定模板、批量应用阈值、批量启用/禁用、批量删除。

---

## 六、安全与审计

- 模板/指标的删除与归档走 `audit_log` 记录。
- 模板版本切换（生产环境）二次确认（输入 "ROLLBACK" 等关键字）。
- 导入全局指标/YAML 走"试运行"模式：先 diff，确认后再写入。

## 七、分阶段实施建议

### Phase 1（1 周）—— 立即可见的 UI 改进
- 指标页加类型图标/颜色/层级（不改 schema，用 `description` 字段做 hack 也可）
- 模板页加分类下拉与"按类型筛选"
- 删除前显示"被多少数据源/模板引用"

### Phase 2（2-3 周）—— 数据模型升级
- 迁移 `metric_types` / `metric_configs` 字段
- 新增 `template_versions` 表
- 实现版本快照与回滚

### Phase 3（1-2 周）—— 高级能力
- 模板 Diff 可视化
- 批量子任务（独立模块）
- 指标标签搜索语法

### Phase 4（持续）—— 跨实例同步
- 全局指标 + 模板的导出/导入做成"插件包"，可在多 PromAI 实例间流转
- 提供官方模板市场（MySQL / Linux / K8s / 等）

## 八、值得做但需要权衡的取舍

| 取舍 | 倾向 |
|---|---|
| 类型支持无限层级 vs 只做二级 | **二级**（足够用，过深导航反人类） |
| 模板版本号语义化（v1.2.3） vs 自增整数 | **整数 + note**（轻量，避免复杂规则） |
| 批量操作进度走 SSE vs 轮询 | **SSE**（更顺滑；后端用现有 `pkg/notify` 基础设施扩展） |
| 模板共享走"模板市场"中心化 vs 纯导入导出 | **优先导入导出**（市场是长期目标） |

---

## 九、可立刻落地的"小改进"清单（不需大改）

1. 指标表格列宽调整 + PromQL 默认 ellipsis
2. 模板页加"按指标数排序"和"按更新时间排序"
3. 删除类型/指标/模板前显示"被引用数"
4. 模板详情页加"已绑定数据源"列表 + 一键解绑
5. 全局指标"应用到数据源"前先 diff
6. 巡检报告里附"本次巡检使用的模板版本号"

这些改进 1-3 天可完成一版，零风险上线。
