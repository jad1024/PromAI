## 📢 维护模式 - 研发人员自助使用说明
### 背景
> 以往发版维护时候研发人员如果想要进行系统调试，此时需要配置一堆白名单IP，IP地址经常变动，对运维来说压力较大，配置过多容易出错，容易冗余无效配置，

> 当服务开启维护模式时，所有用户默认看到维护图片，跳转到特定的维护页面，只有携带特定 Cookie 的研发人员可以正常访问服务，供研发人员调试系统使用

### 收益说明
1. 后续不再需要进行维护一堆白名单IP地址
### 运维人员操作
0. 前置准备
> nginx.conf添加http块全局变量
```bash
    # ---------- 白名单判断 ----------
    # 0 = 不允许访问（跳转维护页）
    # 1 = 允许访问（正常服务）
    map $cookie_gray_user $access_allowed {
        default 0;      # 没有 Cookie 或值不匹配 → 不允许
        "true"  1;      # Cookie = true → 允许
        "1"     1;      # Cookie = 1 → 允许
        "vip"   1;      # Cookie = vip → 允许
        "admin" 1;      # Cookie = admin → 允许
        "on"    1;      # Cookie = on → 允许
        "yes"   1;      # Cookie = yes → 允许
    }
```
> 在对应的Server配置文件添加如下配置，用于管理是否开启维护
```bash
# ==========================================
        # 维护模式控制端点
        # ==========================================

        # 开启维护模式（设置 Cookie）
        location = /maintenance-on {
            # ✅ 添加正确的 Content-Type
            add_header Content-Type "text/html; charset=utf-8";
            add_header Set-Cookie "gray_user=true; Path=/; Max-Age=86400; Secure; HttpOnly; SameSite=Lax";
            add_header Cache-Control "no-cache, no-store, must-revalidate";
            return 200 "
                <html>
                <head><title>维护模式已开启</title></head>
                <body>
                    <h1>✅ 维护模式已开启</h1>
                    <p>你已获得访问权限，可以正常访问服务。</p>
                    <p><a href='/'>返回首页</a></p>
                    <p style='color:#999;font-size:12px;'>Cookie 有效期 24 小时</p>
                </body>
                </html>
            ";
        }

        # 关闭维护模式（清除 Cookie）
        location = /maintenance-off {
            # ✅ 添加正确的 Content-Type
            add_header Content-Type "text/html; charset=utf-8";
            add_header Set-Cookie "gray_user=; Path=/; Max-Age=0; Secure; HttpOnly; SameSite=Lax";
            add_header Cache-Control "no-cache, no-store, must-revalidate";
            return 200 "
                <html>
                <head><title>维护模式已关闭</title></head>
                <body>
                    <h1>✅ 维护模式已关闭</h1>
                    <p>你已退出维护模式，取消访问权限，正常跳转维护页面。</p>
                    <p><a href='/'>返回首页</a></p>
                </body>
                </html>
            ";
        }

        # 查看当前状态（调试用）
        location = /maintenance-status {
            # 添加正确的 Content-Type
            add_header Content-Type "application/json; charset=utf-8";
            add_header Cache-Control "no-cache, no-store, must-revalidate";
            access_log off;
            if ($access_allowed = 1) {
                return 200 "{\"maintenance\": false, \"cookie\": \"$cookie_gray_user\", \"access\": \"allowed\"}\n";
            }
            return 200 "{\"maintenance\": true, \"cookie\": \"$cookie_gray_user\", \"access\": \"denied\"}\n";
        }

        # ==========================================
```
1. 挂载维护页面
> 对应的location 下面添加下面的配置即可
```bash
if ($access_allowed = 0) {
     return 302 https://hmb-010-insurance.webao99.com/0617.jpg;
}
```
1. 取消挂载维护页面
> 对应的location 下面添加下面的注释下面的配置即可
```bash
# if ($access_allowed = 0) {
#      return 302 https://hmb-010-insurance.webao99.com/0617.jpg;
# }
```
### 🔑 如何获取访问权限

在浏览器中访问以下地址，即可获得 24 小时的有效访问权限，此时研发运维人员可进行服务调试；

```
https://对应维护域名/maintenance-on
```

访问后会看到提示：**"✅ 维护模式已开启"**

点击页面上的 **"返回首页"** 链接，或者重新打开目标链接，即可正常访问调试服务。


### ❌ 如何退出维护模式

如需退出维护模式（回到维护图片页面），访问：

```
https://对应维护域名/maintenance-off
```


### 🔍 如何查看当前状态

访问以下地址可查看当前的维护状态和权限信息：

```
https://对应维护域名/maintenance-status
```

返回示例：
```json
// 有权限（可正常访问）
{"maintenance": false, "cookie": "true", "access": "allowed"}

// 无权限（看到维护图片）
{"maintenance": true, "cookie": "", "access": "denied"}
```


### 📱 手机端操作

在手机浏览器中直接点击上面的链接即可，无需任何额外操作。


### 💡 注意事项

| 事项 | 说明 |
|------|------|
| **有效期** | Cookie 有效期为 24 小时，过期后需重新访问 `/maintenance-on` |
| **适用浏览器** | 所有浏览器均可，包括 Chrome、Safari、微信内置浏览器等 |
| **无需登录** | 不需要系统账号，直接访问链接即可 |
| **与其他 Cookie 不冲突** | 不影响现有的登录态或其他业务 Cookie |


### 🧪 快速测试流程

1. 服务开启维护模式
2. 研发人员访问 `https://对应维护域名/maintenance-on`
3. 点击"返回首页"，验证功能是否正常
4. 测试完成后，可访问 `/maintenance-off` 退出
