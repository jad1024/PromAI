# LTS 日志查询

当用户要查某个服务的日志、问"这个报错什么情况"、或需要结合日志定位根因时，使用此工作流。日志全部为 Java 应用日志，查询结果会自动降噪折叠（IP/数字/UUID/时间戳归一、堆栈折叠、logger 统计、traceId 提取），避免把上万行原始日志直接塞进分析。

## 步骤

### 1. 确认检索目标

从用户描述中提取：服务名 / IP / 错误码 / 关键字 / 时间范围。若用户未说明时间，默认最近 15 分钟。

### 2. 查询日志

```
query_lts(keywords="<关键字>", time_range_minutes=15)
```

- 关键字用服务名、报错关键字、错误码（如 ORA-*、Exception、订单号、IP）等
- 日志组/流未指定时会从启用的触发规则自动推断；若告警来自特定告警源，可用 `source_id` 指定
- 时间窗最大 60 分钟

### 3. 解读折叠摘要

返回内容含：
- 折叠模式（签名 + 出现次数 + 首次/末次时间 + 级别 + logger）
- 每模式的采样原文（完整，含堆栈）

判断要点：
- ERROR 集中在哪个 logger（如 com.xxx.OrderService）本身就是定位信号
- traceId 可关联同链路的 WARN→ERROR 序列
- 高频重复模式 → 集中性故障；散乱低频 → 需扩大时间窗或换关键字

### 4. 二次深挖（可选）

若首查证据不足，用更窄的关键字或放宽时间窗再查一次（单次分析最多调用 query_lts 2 次）。

### 5. 给结论

结合日志证据回答用户：最可能根因、证据链（异常类型/logger/traceId）、处置建议。若日志不足以定论，明确说明缺口与建议补充检索的关键字/时间窗。

## 常见场景

### 服务报错定位
1. `query_lts(keywords="<服务名>", time_range_minutes=15)`
2. 看折叠摘要中异常类型与 logger 分布
3. 结合采样原文的堆栈，定位具体代码路径
