PromAI 智能告警与巡检平台

近期功能升级与成果汇报

一、总体成果

近两日完成 5 个核心功能升级，累计改动 25 个文件、约 2200 行代码，全部已提交并推送至 GitHub 主分支。本次升级围绕"用得更顺、看得更清、查得更准"三个维度，覆盖告警治理、巡检重构、新增主动端口扫描、AI 分析能力增强四大方向。

核心价值：把原本散落在告警源、巡检、报告里的"噪音"压成"有效信息"，让一线运维在 5 分钟内看清系统健康状况、定位到具体暴露面、配置好自动处置。

二、关键功能升级

功能解决了什么问题实现要点
新功能 敏感端口检测 公网资产是否有数据库/缓存/容器等敏感端口暴露？原来要靠人肉 nmap + 表格对比，无法定期自查。 类 nmap 主动 TCP 探测，内置 36 个分级敏感端口（高/中/低危），支持批量粘贴公网 IP（一行一个，兼容 CIDR、逗号、空格）。手动触发、独立 HTML 报告，不接入告警链路，避免误报噪音。
修复 AI 巡检报告链接 推送飞书的 AI 巡检卡片，报告链接是 http:///api/promai/...（host 为空），点击无法跳转。 新增域名兜底逻辑，优先级：环境变量 PROMAI_PUBLIC_URL > 飞书/钉钉配置的 report_url > localhost:port。彻底解决异步场景下 host 丢失问题。
新功能 平台级告警隔离 巡检"华为云"时，AI 分析把"期货平台（n9e）"的告警也带进 prompt，导致分析结论被混淆。 巡检模板和定时任务均新增"关联告警源"配置（SMN=华为云 / n9e=期货）。AI 分析时仅纳入配置的告警源，任务级优先于模板级，层层隔离。
重构 巡检范围四选一 手动/定时巡检只能选"全部"或"具体指标"，无法按业务模板（如"基础设施层"）批量巡检。 支持 全部 / 按模板 / 按分组 / 按具体指标 四种互斥范围，模板/分组/指标可多选合并。手填和定时任务语义完全对齐。
重构 告警聚合页拆分 Tab 告警聚合页混杂"告警中"和"已恢复"，无法快速区分待处理和历史。 页面顶部增加"告警中 / 已恢复 / 全部"三个 Tab，按状态过滤后展示时间轴和 TOP 噪音排行。
修复 告警聚合四轮 bug 不同告警被错误折叠到同一故障；n9e 规则名误判（用业务维度当 alertname）；实例摘要污染指纹导致同规则不同实例合并。 修复 instance_summary 不参与指纹、labels.rulename 优先级、EnrichInstanceLabels 从 description 提取 IP:端口等 4 处问题，并补充 9 个单元测试兜底。

三、技术亮点

1. 主动探测能力从 0 到 1：新增 pkg/portscan 包，并发 TCP Dial 实现 100 并发 / 2s 超时探测，36 个内置端口含分级，CIDR 展开、批量解析、报告生成一条龙。

2. 告警聚合可观测性提升：故障按 alertname+resource 聚合，事件降噪 + 风暴标记，AI 上下文更精准；新增 9 个聚合单测保障核心逻辑稳定。

3. 巡检链路解耦：巡检范围解析统一走 resolveScopedMetricConfigs，手动/定时/AI 对话三种入口语义一致；告警源隔离统一在 buildInspectionAnalysisPrompt 收口，调用方无需关心。

4. 前端可读性：端口扫描结果从 30+ 列宽表改为"按 IP 分组卡片 + 端口标签 + 筛选器（IP/状态/风险）"，默认只看开放端口，最危险的 IP 排在最上面。

五、下一步建议

1. 部署验证：在测试环境重建镜像后回归核心链路（告警触发 → 聚合 → AI 巡检 → 飞书推送 → 端口扫描），重点验证告警源隔离效果是否符合预期。
